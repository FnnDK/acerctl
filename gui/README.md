# nitro-control-center

nitroctl GUI in Go + Wails v2: a window on top of `nitrod`'s D-Bus API (`docs/api-dbus.md`). It has no hardware logic: every action is a call to the daemon, which validates it and explains a refusal (the error shows up as a notice on screen).

## Layout

```
main.go             window options, single instance, icon; --session, --minimized
agent.go            session agent (daemon/cmd/nitro-tray): "Tray icon" and "Nitro key"
                    options, agent Reload or starting it when it becomes needed
titlebar.go         window decoration per desktop; frameless: button order (GNOME
                    button-layout, via the settings portal or gsettings) and the theme's
                    window-*-symbolic icons, read from the system
app.go              D-Bus ↔ frontend bridge: State() (all properties), write methods,
                    "state" (PropertiesChanged, with reconnection) and "sample" (Monitor) events
frontend/src/       framework-less TypeScript + own CSS; charts with uPlot
  core.ts           state, sample history, calls, formatting, toasts/dialogs
  i18n.ts           pt/en texts (system language or the one chosen in Settings)
  icons.ts          own line icons and the [N] mark
  titlebar.ts       own title bar (drag, double click, minimize/maximize/close)
  pages/            home, monitor, fans, lighting, battery, scenarios, settings
frontend/wailsjs/   bindings generated by Wails (do not edit)
build/appicon.png   generated from assets/logo/n-icon-cut.svg (rsvg-convert -w 512)
```

**Window decoration.** On GNOME and other GTK desktops the window is frameless: the title bar belongs to the app, with rounded corners and a shadow in a transparent margin. On KDE and LXQt (`XDG_CURRENT_DESKTOP`) the compositor draws the frame, so theme, button order and tiling match the other windows, and the GUI's top row shows only the mark. To force one of the two: `NITROCTL_DECORATIONS=client` or `server`. On GNOME, `server` shows the default GTK bar, since Mutter does not decorate Wayland windows.

Screens and controls appear only for what `System.Capabilities` lists (e.g. no Turbo on the ANV15-52). The Monitor is subscribed only while the window is visible on a screen that shows live data; with no subscribers the daemon does not sample.

## Developing (in the container)

Needs `nodejs`, `npm`, `libwebkit2gtk-4.1-dev`, `libgtk-3-dev` and `go install github.com/wailsapp/wails/v2/cmd/wails@latest`. Debian/Fedora only ship WebKitGTK 4.1: always `-tags webkit2_41`.

```bash
../daemon/nitrod --session --simulate ANV15-52 --state /tmp/ns.json &   # fake daemon
NITROCTL_SESSION=1 wails dev -tags webkit2_41    # window + http://localhost:34115 in the browser
```

`wails dev` rejects unknown flags, so the session bus comes from `NITROCTL_SESSION=1` (equivalent to `--session`).

## Installing

```bash
sh packaging/install-gui.sh build                       # container
distrobox-host-exec sudo sh packaging/install-gui.sh    # host: /usr/local/bin, .desktop and icon
distrobox-host-exec sudo sh packaging/install-gui.sh uninstall   # removes the three files
```

The host only needs the `webkit2gtk4.1` runtime (already present on Fedora Silverblue 44).
