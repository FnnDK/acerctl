# acerctl — STATUS (resume point)

Last updated: 2026-10-13. Read this file first; the technical reference is `docs/firmware-wmi.md` (cited below as §N).

## Goal and architecture decision

All-in-one Linux alternative to Acer's NitroSense (working), AcerSense (in progress, Aspire AG15-71P) and PredatorSense (to do), showing each feature only when the firmware offers it. Reproduce their features on Linux **coexisting with the in-tree `acer_wmi`**, without replacing it: whatever is missing comes from (a) upstream patches to `acer_wmi` and (b) out-of-tree companion modules + a daemon + a GUI. No brand flag: capabilities come from the firmware (WMI masks, DMI); a per-model table only for what the firmware does not report. Linuwu-Sense and Div-Acer-Manager-Max are references, not a base (§10).

**Stack decided (2026-10-12):** kernel modules in **C** (`drivers/`), daemon in **Go** (D-Bus service on the system bus, polkit, systemd), 1:1 GUI in **Go + Wails** (web frontend in WebView/WebKitGTK), CLI and tray as clients of the same D-Bus API. Own artwork in the GUI (icons, fonts, animations): no Acer material.

**Names (2026-10-13, renamed from nitroctl/nitrod the same day), following the asusctl scheme:** project, repository and CLI `acerctl`, daemon `acerd`, tray agent `acer-tray`; GUI in two flavors from the same `gui/` code, chosen per product line at install time (branding only, capabilities still come from the firmware): `nitro-control-center` (red `[N]`, Nitro), `predator-control-center` (blue-grey `[P]`, Predator) and `acer-control-center` (green `[a]`, other lines such as Aspire; done 2026-10-13); reverse-DNS prefix `io.github.fnndk` (D-Bus `io.github.fnndk.Acerd1` at `/io/github/fnndk/Acerd1`, polkit `io.github.fnndk.acerd.{control,settings}`, state in `/var/lib/acerd`). "Nitro"/"Acer" only as references to the hardware; the README must say there is no affiliation with Acer.

Reference machine: Acer **Nitro ANV15-52** (i7-13620H, RTX 4060, BIOS V1.31), Fedora Silverblue 44, kernel 7.2.9.

## Work environment

- The terminal runs in a Debian **distrobox** (`deb`). Host commands: `distrobox-host-exec <cmd>`; root on the host: `distrobox-host-exec sudo ...` (asks for a password).
- **Secure Boot on** (`sig_enforce=Y`, lockdown `integrity`): every out-of-tree `.ko` must be signed with the already enrolled akmods MOK:
  `sudo /usr/src/kernels/$(uname -r)/scripts/sign-file sha256 /etc/pki/akmods/private/private_key.priv /etc/pki/akmods/certs/public_key.der module.ko`
  (the signature stays in the file; only re-sign after rebuilding). Lockdown blocks writable debugfs → interfaces in **sysfs**.
- The host has `gcc`, `make`, `kernel-devel`: build with `distrobox-host-exec make -C <module dir>`.
- `tuned` + `tuned-ppd` write to `platform_profile`; keep `tuned` on `balanced` (Linux `performance` = Acer Turbo, which this model does not have).

**Aspire AG15-71P** (Aspire Go 15, i7-13620H, Intel graphics only, BIOS V1.13, EC 1.11, Bluefin 44 / kernel 7.2.5, **Secure Boot off**). Reported through the contributor flow as [issue #1](https://github.com/FnnDK/acerctl/issues/1) (survey v2 with `--probes`, which built acer-wmi-lab on the host by itself; 91/91 AE_OK):
- `acer_wmi` does not load because of `/etc/modprobe.d/blacklist-acer_wmi.conf`, left behind by a Div-Acer-Manager-Max (DAMX) install, which replaces `acer_wmi` with Linuwu-Sense; DMI type 170 is present, so it would bind with the WMID v2 interface.
- Same WMI GUIDs as the ANV15-52; WMI AML in SSDT13: same `WMBH` → SMM dispatcher; `GetGamingSysInfo` cmd 0 hard-coded to mask `0x45` (sensors 1 CPU temp 53 °C, 3, 7); no DPTF/`NPCF` work on profile changes; `WMAA` SetFunction fn 4 (EC `SUCS`) and fn 7 (`ODV0` step + `Notify(IETM, 0x88)`) handled in AML.
- **Not supported via WMI (status 1):** GetGamingProfile, every GetGamingMiscSetting index (no profile mask 0x0A / current profile 0x0B → `predator_v4` cannot give `platform_profile`), fan behavior/speed/table, LEDs, RGB/KB backlight, CPU OC. APGe: keyboard byte 2 = 0 (no backlight), USB charging Get → 0xE1 (not supported).

Request `A0 | 00 A0 | id(lo) id(hi) | sub | args`; response `A0 | status LE (0xE000 = OK) | id echo | data from byte 5`. Ids: 0x0000 system (sub 00 spec version, 01 app status [set], 02 battery boost, 03 AC, 04 OC capability, 05 **mode capability**, 06 mode limit, 07 PD adaptor), 0x0001 **usage mode** (01 set target, 02 get current), 0x0002 whisper/OC profile, 0x0B03 battery boundary (01 set status/upper/lower, 02 get), 0x0B00 battery information, 0x0004 fan (ARM variant). The mode capability is a level, not a mask: 0–2 → Normal only, 3 → Silent/Normal/Performance, 4 → + Turbo, 5 → + Eco. Not confirmed yet: the byte each mode takes in the set command and the battery index argument.

# ready-made batches: drivers/acer-wmi-lab/probe.sh, probe2.sh, probe3.sh; key: keywatch.py

## Agreed rules

- Do not replace `acer_wmi`; do not create brand flags; capabilities from the firmware.
- English only in the repository (code, docs, scripts, commit messages); Portuguese only in the GUI/tray translations and `[pt_BR]` entries.
- Companion name: **`acer-wmi-extras`** (applies from Aspire to Predator).
- Languages: C (kernel), Go (daemon, CLI), Go + Wails (GUI). GUI with own artwork.
- Only "Get" methods in exploratory probes; "Set" only with a validated, reversible format.
- Names: `acerctl` (project/CLI), `acerd` (daemon), `nitro-control-center` / `predator-control-center` / `acer-control-center` (GUI flavors), namespace `io.github.fnndk`.
- Features beyond the original app (e.g. Performance on battery) are allowed, but always **flagged as extra** in the API (`Mode.Extras`) and in the GUI.
- Before persisting options that create `platform_profile`, check the `tuned` profile.
